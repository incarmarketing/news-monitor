# 분류 자동 점검 운영

## 실행

- 기존 Classification Audit 작업이 매일 06:37 KST 예약으로 실행됩니다. GitHub 예약 실행은 지연될 수 있습니다.
- 분류 코드가 main에 반영되면 같은 검사를 읽기 전용으로 실행합니다.
- PC가 꺼져 있어도 서버에서 실행합니다. 추가 AI API는 사용하지 않습니다.
- 최근 7일 수집분을 최대 2,500행 검사하며, 초과하거나 조회가 불완전하면 보정을 중단합니다.

## 자동 변경 범위

검토 완료된 원문 주제·역할 규칙을 다시 적용합니다. 현재 자동 변경 대상은 보험업 근거가 없는 은행·증권 일반 기사, 통신 민원, 보험사 연구소를 출처로만 인용한 연애 설문, 보험사 구단 경기 기사입니다. 보험 상품·계약·모집·자본·규제 근거가 있으면 제외하지 않습니다.

다음은 자동 변경하지 않습니다.

- 사용자가 분류를 수정한 기사
- 당사 직접 언급 기사, 기존 당사 분류 기사
- 기존 부정 기사나 경보 대상 기사
- 검증된 제외 규칙 밖의 분류 불일치

새 키워드나 규칙을 자동으로 만들어 활성화하지 않습니다. 불일치는 검토 후보이며, 오분류가 확정됐거나 정확도가 측정됐다는 뜻이 아닙니다. 부정 경보 검증 지표 역시 검토된 표본의 결과이지 전체 기사 정확도 보장이 아닙니다.

## 안전장치

- 기존 회귀 테스트와 DB 검토 사례 검증을 통과해야 보정합니다.
- 1회 25건 또는 검사량의 5%를 넘으면 전체 자동 변경을 차단합니다.
- 반영 직전에 수동 분류와 규칙 변경을 다시 확인합니다.
- 기사 원본이나 분류가 검사 이후 바뀐 건은 건너뜁니다.
- 상위 분류 컬럼과 원문 캐시의 분류를 한 트랜잭션에서 함께 갱신합니다.
- 변경 전 원본과 변경 후 값은 비공개 DB 이력에 함께 보관합니다.
- 같은 실행 ID의 재시도는 중복 보정하지 않습니다.
- 신규 기사를 삭제하거나 Slack 부정 알림을 추가 발송하지 않습니다.

## 결과 확인과 중단

- [자동 점검 실행 이력](https://github.com/incarmarketing/news-monitor/actions/workflows/classification-audit.yml)의 Summary와 `classification-audit-reports` 첨부 결과를 확인합니다. 첨부 파일은 30일 보관합니다.
- 비공개 `classification_maintenance_runs`에는 검사 결과와 실제 변경 전후 이력이 보관됩니다. 브라우저·일반 로그인 사용자에게 직접 조회·실행 권한이 없습니다.
- 저장소 Actions 변수 `CLASSIFICATION_MAINTENANCE_PAUSED=true`로 자동 보정만 중단할 수 있습니다. 읽기 전용 검사는 계속합니다.
- 수동 실행의 `apply_repairs`는 같은 안전 범위에만 적용됩니다. `full_history`는 기존 전체 누적 감사 도구를 읽기 전용으로 추가 실행합니다.
- 장애 때는 데이터를 비우거나 검사 성공으로 표시하지 않고 작업을 실패 처리합니다. DB 이력도 저장할 수 없는 경우 GitHub 첨부 결과가 남습니다.

## 규칙 개선 절차

검토 후보에서 원문 근거를 확인하고, 정답 사례와 혼동하기 쉬운 반례를 함께 테스트에 추가합니다. 새 규칙은 기존 테스트와 최근 기사 재검사를 통과시킨 뒤 배포합니다. 이후 매일 같은 검사가 되풀이되므로 기존 오류의 재발과 분류 적용 누락을 계속 확인할 수 있습니다.

SQL 보호 장치 시험은 `tests/sql/classification_maintenance.sql`을 사용합니다. 전체 시험이 트랜잭션 안에서 실행된 뒤 롤백됩니다.
