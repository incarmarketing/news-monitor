# 언론사·기자 누적 이력

- 당사 언급(`own_mentioned=true`)을 기준으로 전 기간을 집계한다. 기사 분류명이 `own`인지와 무관하다.
- 언론사, 기자, 기사 이력은 관리 화면에서만 조회한다. 첫 화면에서 누적 기사를 다운로드하지 않는다.
- 언론사 미확인 목록은 전체 DB의 미확인 기사를 주소별로 묶으며, 기사 목록은 30건씩 조회한다.
- 포털 주소는 일괄 지정할 수 없다. 기사 해시별 확정값이 재수집보다 우선한다.
- 언론사와 기자 자동 등록은 수동 메모·관계·연락처를 덮어쓰지 않는다.
- 기자는 기사 작성자 메타데이터와 바이라인으로만 확인한다. 인터뷰 대상자, 언론사명, 부서명, 추천 기사 기자를 제외한다.
- 기자 이메일은 작성자에 연결된 공개 업무 이메일만 비공개 CRM에 저장한다. 공개 조회는 이름·기사·확인 출처·확인일만 제공한다.
- 별도 증거 테이블에 보관하여 기사 raw 재수집에 의해 기자 확인 결과가 지워지지 않는다.
- 기존 정규 브리핑이 발송·기록된 뒤 최대 20건, 3분 한도로 보강한다. 10분 감시 경로에는 추가하지 않는다.
- 원문 접속 실패는 하루 이상 간격으로 최대 3회 확인한다. 새 원문 주소가 확보되면 다시 확인한다. robots.txt와 공개 URL 제한을 적용한다.

## 검증

- 최초 누적 971건 점검, 오인 가능 50건 재검증, 추가 추천 기사 혼입 2건 재검증 후 반영.
- 538건에서 작성자 확인, 언론사·이름 조합 170개 프로필 등록. 공개 업무 이메일 77개 프로필.
- 당사 보도 매체 153곳, 미확인 기사 268건. 조회 시점에 따라 이후 증가할 수 있다.
- `tests/media_registry_regression.sql`: 서비스 권한으로 실행하는 rollback-only DB 검증. 수동 값 보존, 멱등성, 페이지 나눔, 연락처 비노출, 포털 일괄 매핑 차단, 재수집 후 확정 유지.
- `tests/test_media_byline.py`: 작성자 추출·오인·SSRF·등록 기준 검증.
- `tools/verify-media-registry.mjs`: PC/모바일, 비로그인 실패, 주소별/기사별 저장, 원문 링크, 페이지 나눔, 오류 시 기존 데이터 보존.

미확인 항목은 사람이 확인할 수 있게 남기며, 확인되지 않은 기자·연락처를 추정해서 채우지 않는다.
