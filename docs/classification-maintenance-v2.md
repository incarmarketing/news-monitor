# 분류 자동수정 v2

## 적용 상태

2026-09-15 사용자 승인 후 운영 DB 마이그레이션과 보호 장치 시험을
완료했다. 시험 변경은 모두 롤백됐으며 `test-v2-*` 이력 0건을 확인했다.
익명·일반 로그인 사용자의 실행 권한은 차단 상태를 유지하고, 기존
서버 실행 권한만 유지한다. 코드·API는 기존 GitHub 자동배포 경로로
반영하며, 실제 기사 수정 결과는 비공개 점검 이력과 재조회 검증에 남긴다.

## 변경 범위

- 과거 정답 사례의 분류·논조를 변경하지 않는다. 경보 정답을 당사+부정에서
  추정하지 않으며, 독립 검토가 없는 값은 미측정으로 표시한다.
- 기존 검토 사례의 화면 노출 정답도 평가한다. 이는 분류상 노출 여부이며,
  당일 여부·정렬·TOP 5 선정까지 평가했다는 뜻은 아니다.
- 독립 회귀 사례 72건으로 당사 언급, 경보 정밀도·재현율을 검증한다.
  이는 작성된 시험 사례의 결과이며 전체 운영 기사 정확도 추정치가 아니다.
- 신규/원문 과거/최초 발견 과거/미래 날짜 4개 사례는 실제 부정 감시의
  날짜 판정 함수로 별도 검증한다. 알림 발송이나 이력 조회는 하지 않는다.
- 유형별 수정·보호 반례 20개를 모두 통과한 유형만 허용한다.
  당사 언급 검증 100%, 경보 정밀도 99%·재현율 90% 기준은 공통 적용한다.
- `source_role`: 기존 업종 무관 기사 정리 범위를 유지한다.
- `insurance_subject`: 기존 보험사/GA 분류 사이에서 원문 주체가 명확한
  중립 기사만 재분류한다. 논조를 바꾸거나 당사·부정·경보를 변경하지 않는다.
- 기존 수동 수정, 당사 언급, 부정, 경보 보호 및 7일·25건·5% 상한을 유지한다.
- GA코리아 위반 규칙에서 회사명 자체를 위반 신호로 쓰던 조건을 제거한다.
  회사명과 구체적 위반 문맥이 함께 있어야 해당 주의 규칙을 적용한다.

## 자동 운영

기존 일일 Classification Audit 안에서 실행한다. 별도 스케줄러나 AI API를
추가하지 않는다. 코드 push는 읽기 전용 검사, 정기 실행과 승인된 수동
실행만 안전 범위 안에서 수정한다.

원문 부족 후보는 정기 검사에서 최대 5건만 추가 확인한다. 같은 입력은
24시간 간격, 최대 3회로 제한하며 원문이 바뀌면 다시 검사할 수 있다.
공개 URL·robots 제한을 확인하고 본문 영역만 읽는다. 사진 설명·관련 기사·
저작권 영역·전체 페이지 문단을 본문 근거로 승격하지 않는다.
확보한 원문과 재분류 제안은 비공개 점검 이력에만 남는다. 당사·논조·경보
변경을 원문 수집만으로 자동 승인하지 않는다.

수동 수정 기록은 매일 원래 규칙만으로도 재검사한다. 규칙과 불일치하는
부분을 운영관리의 '수동 수정 재검사'에서 확인한다. 수동 수정 자체는
유지하며, 불일치가 무조건 규칙 오류라는 뜻도 아니다. 새 규칙 자동 활성화는 없다.

반영 직전 구성 변경과 기사 동시 수정을 검사하고, 상위 분류·원문 캐시를
같은 트랜잭션에서 변경한다. 적용 후 재조회로 일치 여부를 기록한다.
동시에 발생한 언론사 메타데이터 보강은 분류 충돌로 오인하지 않는다.
확인된 변경이 있으면 기존 Pages 배포를 요청한다. 과거 Slack 메시지를
재발송하지 않으며 발송 당시 보고서의 역사적 내용도 일괄 덮어쓰지 않는다.

- 프론트 단위 시험 171개, API 시험 24개 통과.
- Vite 빌드 통과.
- 1366/1920/390px 화면에서 탭, 페이지 이동, 지연 로딩, 실패 표시,
  빈 결과와 권한 차단을 검증했다. 브라우저 오류 0건.
- 최근 7일 827건, 30일 3,676건 스냅샷을 각각 3회 재검사했다.
- 7일 수정 후보 7건, 30일 분석 후보 370건. 두 번째·세 번째 시험 적용은
  추가 변경 0건이다. 입력과 보호 대상 보존을 assertion으로 검사했다.
- 30일 후보는 운영 반영 대상이 아니다. 실제 수정은 승인 후 최신 7일을 다시 검사한다.
- 운영 DB에서 유형·공통 검증 실패, 원문 변경, 규칙 동시 변경, 중복 ID,
  건수 상한, CAS, 정상 수정, 재실행, 백업, 부정 보호 시험을 모두 통과했다.
- 기존 검토 표본과 새 시험 표본의 지표를 합쳐 전체 정확도라고 표시하지 않는다.

## 적용 절차

1. 최신 DB 규칙이 바뀌지 않았는지 재확인한다.
2. `20260915005238_scoped_classification_maintenance.sql`을 적용한다.
   검증 테이블 두 개에 nullable 정답 컬럼 두 개씩 추가하고 보호 함수를
   확장한다. 익명·로그인 사용자에게 자동수정 실행 권한을 추가하지 않는다.
3. `tests/sql/classification_maintenance_v2.sql`을 실행한다. 시험 변경은
   모두 롤백되며 결과가 통과해야 한다. SQL 시험은 새 함수 적용 후에만 의미가 있다.
4. 코드 배포 및 Classification Audit 읽기 전용 검사 결과를 확인한다.
5. 최신 7일 데이터를 다시 검사한 뒤 안전 상한 안에서만 1회 반영한다.
6. 반영 이력, 재조회 확인, 캐시와 화면을 확인한다. 실패하면 자동수정을
   일시 중단하고 충돌 원인을 확인한다. 상한과 경보 보호를 완화하지 않는다.
